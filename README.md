# ООП — лабораторная работа 2

Минимальный учебный проект по заданию «Объекты и классы», страницы 3–4 методички ООП 2025.
Учебный проект подготовлен с опорой на
[пример ArthurDavletov/uust_oop, lab_2](https://github.com/ArthurDavletov/uust_oop/tree/main/lab_2).
Консоль, C++11, без сторонних библиотек.

| Пример старшекурсника | Минимальный проект |
| --- | --- |
| Point, его конструкторы и координаты | Point: те же три обязательных способа создания, Move и Print |
| ColoredPoint, вызов Point::ToString | ColoredPoint: невиртуальный Print вызывает Point::Print |
| Circle с полем Point center_ | Circle с непосредственным полем Point |
| SegmentPtr с владеющими указателями | Тот же принцип на одном центре CirclePtr, с глубоким копированием |
| InspectableShape без своих конструкторов | PlainPoint без своих конструкторов и деструктора |
| Отдельные демонстрации в main | Пять последовательных блоков, соответствующих требованиям ЛР2 |

В примере есть virtual, абстрактные Shape/ClosedShape, std::format и перемещение.
В минимальный проект включены только обязательные для второй лабы механизмы.
Копирование владеющего CirclePtr при присваивании запрещено, чтобы не допустить двойной delete.

## С чего начать

1. Открой `lab_2/START_HERE.md` — короткая инструкция.
2. Открой `lab_2/main.cpp` — сценарии демонстрации.
3. Изучай `lab_2/THEORY.md` одновременно с исходниками.
4. Сверь обязательные пункты с `lab_2/REQUIREMENTS.md`.

Основная программа состоит из трёх файлов: `main.cpp`, `objects.h`, `objects.cpp`.
Четыре основных класса и один пустой наследник для отдельного вопроса методички.

## Git

В общих требованиях методички Git обязателен со второй лабораторной.
GitHub не обязателен: разрешён локальный репозиторий. На защите нужна история коммитов.
Локальная история создана по фактическим этапам работы; даты не подменялись.

Из папки проекта:

```powershell
git log --oneline --reverse
git status
```

После собственного изменения и проверки программы:

```powershell
git add lab_2
git commit -m "Describe the actual change"
```

Архив проекта должен включать папку `.git`, иначе история потеряется.
Обычный Download ZIP на GitHub историю не сохраняет: для неё нужен `git clone`.

### Репозиторий на GitHub

[hackleska-ship-it/uust_oop](https://github.com/hackleska-ship-it/uust_oop)
содержит папку `lab_2`, исходники, теорию и историю этапов разработки.

Чтобы скачать работу вместе с историей:

```powershell
git clone https://github.com/hackleska-ship-it/uust_oop.git
cd uust_oop
git log --oneline --reverse
```

Шесть этапов разработки перенесены на GitHub с тем же содержимым файлов
и теми же сообщениями коммитов. При переносе через подключение GitHub
созданы новые коммиты; исходная локальная история сохранена в ветке
`local-development` на этом компьютере.

В рабочей папке настроен удалённый репозиторий `origin`. После собственного
изменения, проверки и коммита отправить изменения можно командой `git push`.
При первой отправке Git может отдельно попросить войти в GitHub:
вход в браузере и вход для команд Git — разные сессии.
Пароль или токен не нужно вписывать в файлы проекта.

## Проверка

Объединённая для проверки копия трёх исходников успешно собрана и выполнена
в Compiler Explorer, x86-64 GCC 16.2, с параметрами:

```text
-std=c++11 -Wall -Wextra -pedantic -Werror
```

Программа завершилась с кодом 0, ошибок и предупреждений компилятора не было.
Проверены независимость копий, общий объект у двух указателей, порядок
конструкторов/деструкторов и обе композиции. Проверка санитайзером не выполнялась.
Точная копия наблюдавшегося вывода находится в `lab_2/EXPECTED_OUTPUT.txt`.
Дополнительно оба .cpp-файла собраны отдельно одной командой на Windows:
переносной Zig 0.17.1 (`zig c++`), C++11, `-Wall -Wextra -pedantic -Werror`.
Полученный `lab_2/build/lab2.exe` запущен на этом компьютере: код завершения 0,
вывод полностью совпал с EXPECTED_OUTPUT.txt. Также проверен запуск через run.bat.

Компилятор находится в `tools/zig` в рабочей папке и автоматически используется
build.bat / run.bat. Он не добавлялся в системный PATH; административная установка не нужна.
Папка tools и промежуточные результаты не коммитятся в Git.
В небольшой архив включена готовая программа `lab_2/build/lab2.exe`, но не весь компилятор.
На другом компьютере demo.bat запускает готовую программу, а для пересборки нужен компилятор.

Для VS Code можно открыть `oop-labs.code-workspace`; `Ctrl+Shift+B` запускает сборку.
Сами исходники остались в трёх файлах, без дополнительных возможностей поздних лабораторных.

Это материал для изучения и самостоятельной доработки: методичка требует
самостоятельного выполнения и понимания кода на защите.
