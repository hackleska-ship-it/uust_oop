# Сборка и запуск

## Файлы программы

`objects.h` содержит определения классов, `objects.cpp` — реализации методов,
`main.cpp` — сценарии их использования. Оба `.cpp`-файла нужно включать в сборку.

## Windows

Открой папку `lab_2` и запусти `run.bat`. Скрипт собирает программу и оставляет
окно с выводом открытым. `build.bat` выполняет только сборку, `demo.bat` — только
запуск существующего `build\lab2.exe`. После изменения исходников нужна пересборка.

Для сборки установи один из компиляторов:

- g++ с доступной командой `g++`;
- Visual C++: запуск из Developer Command Prompt for Visual Studio;
- Zig: положи переносной компилятор в `tools/zig` в корне репозитория или задай
  переменную окружения `ZIG_EXE` с полным путём к `zig.exe`.

Компилятор и готовая программа не входят в содержимое GitHub-репозитория.
В VS Code можно открыть `oop-labs.code-workspace` и собрать программу сочетанием
`Ctrl+Shift+B`. Редактор и расширение C/C++ не заменяют компилятор.

Вызов из терминала в папке `lab_2`:

```bat
build.bat
build\lab2.exe
build\lab2.exe point
```

`run.bat [раздел] [--no-pause]` пересобирает и запускает указанный раздел;
`demo.bat [раздел] [--no-pause]` запускает существующую сборку. Без раздела
выполняется `all`. Флаг `--no-pause` отключает ожидание нажатия клавиши.

## g++ и CMake

Из папки `lab_2`:

```sh
g++ -std=c++11 -Wall -Wextra -pedantic -Werror objects.cpp main.cpp -o lab2
```

В Linux/macOS запуск: `./lab2`; в Windows при сборке в `lab2.exe`: `lab2.exe`.

Альтернативная сборка из корня репозитория:

```sh
cmake -S lab_2 -B lab_2/build
cmake --build lab_2/build
```

Одноконфигурационный генератор создаёт `lab_2/build/lab2` (в Windows —
`lab2.exe`), Visual Studio — `lab_2/build/Debug/lab2.exe`.

## Разделы демонстрации

| Аргумент | Что выполняется |
| --- | --- |
| `point` | Три конструктора Point, присваивание, независимость объектов, общий объект у двух указателей |
| `plain` | Наследник PlainPoint без собственных конструкторов и деструктора, его неявное копирование |
| `inheritance` | ColoredPoint, порядок создания и уничтожения, невиртуальные методы, базовые указатели и срезка |
| `value` | Circle с полем Point, автоматическое создание и уничтожение поля |
| `pointer` | CirclePtr с владеющим Point*, глубокое копирование и освобождение памяти |
| `all` или без аргумента | Все пять разделов по порядку |

Неизвестный аргумент или лишние аргументы выводят подсказку и завершают программу
с кодом 2. Успешный запуск возвращает 0.

`Point()` обозначает конструктор без параметров, `Point(copy)` — конструктор
копирования, `~Point` — деструктор. Сообщения вывода используют ASCII и одинаково
отображаются в разных консолях. Полный вывод приведён в `EXPECTED_OUTPUT.txt`.

Теория и задания для подготовки к защите находятся в `THEORY.md`, соответствие
обязательным пунктам методички — в `REQUIREMENTS.md`.
