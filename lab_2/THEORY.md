# Теория для защиты с нуля

Читай по одному разделу и проверяй его на программе. Это материал именно к ЛР2.
Наличие готового кода не заменяет умения объяснить его и изменить на защите.

## 1. Из чего вообще состоит программа

Переменная хранит значение. `int x = 3;` создаёт целочисленную переменную x со значением 3.
Тип отвечает на вопрос, какие значения и действия допустимы.
Функция — именованный участок кода, который можно вызвать.
Выполнение нашей программы начинается с функции `main()`.
Фигурные скобки `{ }` ограничивают блок кода. Большинство инструкций заканчивается `;`.
`return 0;` в main сообщает об успешном завершении.
`std::cout` выводит текст и числа, `<<` передаёт очередную часть вывода,
`'\n'` переводит строку. Мы используем стандартный поток, а не пишем свои перегрузки `<<`.

`#include <iostream>` подключает объявления стандартного ввода-вывода.
`#include "objects.h"` подключает наше описание классов.
`.h` содержит определения классов и объявления методов, `.cpp` — реализации.
Компилятор обрабатывает main.cpp и objects.cpp, затем компоновщик соединяет результаты.
Если забыть добавить objects.cpp в сборку, можно получить ошибку о ненайденной реализации метода.
`#ifndef` / `#define` / `#endif` не дают повторно определить классы при повторном подключении заголовка.

## 2. Класс, объект, поле и метод

Класс — описание собственного типа. Объект — конкретный экземпляр этого типа.
Point — класс, `Point original(1, 2);` создаёт объект original.
Поле (атрибут) — данные внутри объекта: x_, y_.
Метод — функция класса, работающая с объектом: Move, Print.
У каждой точки свои координаты. Само определение `class Point` точку не создаёт.
`original.Move(10, 0)` вызывает Move у original. Точка `.` используется для объекта,
стрелка `->` — для доступа через указатель.
Подчёркивание в конце x_ — выбранный стиль имени, не особая команда C++.

Инкапсуляция — объединение данных с действиями и управление доступом к этим данным.
Наши координаты закрыты, а менять их можно через Move.
Абстракция — выделение существенного: точка описана координатами и действиями,
без деталей экрана или интерфейса. Абстракция и абстрактный класс — разные понятия.

## 3. Доступ: public, private, protected

| Модификатор | Кто имеет доступ в нашем примере |
| --- | --- |
| public | Код снаружи класса, сам класс и его наследники |
| private | Сам класс; наследник напрямую не обращается |
| protected | Сам класс и его наследники; main напрямую не обращается |

Уточнение: существуют друзья класса (`friend`), но в нашей работе их нет.
Private не означает «данных нет в наследнике»: они остаются в базовой части,
но прямой доступ к ним из методов потомка запрещён.

`original.x_ = 5;` запрещено. `original.Print()` разрешено.
`original.PrintCoordinates()` из main запрещено, из ColoredPoint::Print разрешено.
В классе Point метод копирования читает `other.x_`: private ограничивает доступ
по классу, а не разрешает читать только текущий экземпляр.
В `class` доступ по умолчанию private, в `struct` — public.

## 4. Конструкторы, список инициализации, деструктор

Конструктор выполняется при создании объекта, имеет имя класса и не имеет типа результата.

```cpp
Point a;          // Point(): (0, 0)
Point b(1, 2);    // Point(int, int): (1, 2)
Point c(b);       // Point(const Point&): новая независимая копия b
Point d = b;      // Тоже создание копии, хотя написан знак =
a = b;           // a уже существует: присваивание, не конструктор
```

`Point::Point(int x, int y) : x_(x), y_(y)` — список инициализации после двоеточия.
Сначала поля создаются с указанными значениями, затем выполняется тело `{ ... }`.
`x_(x)` означает «инициализировать поле x_ параметром x».
Поля инициализируются в порядке их объявления в классе, независимо от порядка в списке.
Если поле — объект другого класса, в этот момент вызывается его конструктор.

Деструктор имеет имя `~Point()`, не принимает аргументов и не имеет типа результата.
Он выполняет завершающие действия при уничтожении объекта.
Уничтожение локального объекта происходит автоматически при выходе из его блока.
Локальные объекты в одном блоке уничтожаются в порядке, обратном завершению их создания.
Например, в PointDemo сначала исчезает copy, затем original, затем first.

У динамического объекта `delete` вызывает деструктор и освобождает выделенную память.
Ручной вызов `p->~Point()` не является заменой delete: он не освобождает выделенную через new память.

## 5. Символы &, *, ::, const, this

| Запись | Что означает |
| --- | --- |
| `Point* p` | p — указатель на Point |
| `&a` | Получить адрес объекта a |
| `*p` в выражении | Получить объект, на который указывает p |
| `Point& ref = a` | ref — ссылка, другое имя существующего a |
| `const Point& other` | Передать объект по ссылке, без копии, запретить его изменение через other |
| `Point::Print` | Метод Print принадлежит классу Point |
| `Point::Print()` внутри потомка | Явно вызвать реализацию Point |
| `Print() const` | Метод не изменяет обычные поля текущего объекта |
| `this` | Указатель на объект, для которого сейчас вызван нестатический метод |

Значение символа зависит от места: & в объявлении ссылки отличается от & при получении адреса.
`const` перед Point& относится к объекту-параметру, `const` после скобок — к текущему объекту.
GetX написан внутри определения класса. Такой метод неявно inline,
но это не гарантирует, что компилятор физически подставит его тело вместо вызова.

## 6. Указатели — главный разбор

```cpp
Point* p = new Point(3, 4);
```

По шагам: объявляется переменная p типа «указатель на Point»; new выделяет память;
в ней конструктор создаёт Point; new возвращает адрес; адрес записывается в p.
Здесь одна переменная-указатель и один отдельный динамический объект.
Указатель хранит адрес, а не «точку целиком».

```cpp
Point* q = p;
q->Move(100, 0);
```

Нового Point нет. p и q содержат адрес одной точки. Через оба теперь видно (103, 4).
`q->Move(...)` по смыслу равнозначно `(*q).Move(...)`.
Присваивание одного указателя другому не вызывает конструктор копирования Point.
Указатели можно перенаправлять. Ссылка при обычном использовании привязана к исходному объекту;
присваивание через неё изменяет этот объект, а не перепривязывает ссылку.

```cpp
delete p;
p = nullptr;
q = nullptr;
```

Удаляем точку один раз. Сразу после delete оба старых адреса непригодны для обращения к точке.
Обнуление p само по себе не изменяет q. Поэтому оба указателя обнуляются отдельно.
`nullptr` — пустой указатель; разыменовывать его нельзя. `delete nullptr` допустим и ничего не делает.
Уход локальной переменной p из области видимости не вызывает delete для динамической точки.

В методичке `Point a;` назван «статическим созданием». Точный термин C++ для такого
локального объекта — автоматическая длительность хранения. Ключевого слова static здесь нет.
Локальный объект обычно размещается в стеке, динамический — в динамической памяти
(часто говорят «куча»), но правила языка о времени жизни важнее физического размещения.
Локальный указатель может указывать на динамический объект: место хранения указателя
и место хранения объекта — разные вопросы.

## 7. Контроль памяти и ошибки

| Ошибка | Пример смысла | Как избегаем |
| --- | --- | --- |
| Утечка | Забыли удалить динамический объект или потеряли его последний адрес | Ясно назначаем владельца и соответствующий delete |
| Двойное удаление | delete p, потом delete q, где оба хранили один адрес | Один владелец, один delete |
| Обращение после удаления | Вызвать p->Print после delete p | Не использовать старые адреса |
| Пустой/неинициализированный указатель | Вызвать метод, когда корректного объекта нет | Инициализировать указатели и проверять допустимость обращения |
| Неверная пара выделения/освобождения | Удалить new[] через delete | new/delete, new[]/delete[]; массивов у нас нет |
| Удаление чужого объекта | Сделать delete &localPoint | Не удалять обычные локальные объекты через delete |

Сырой указатель не сообщает, владеет ли он объектом. Это определяется устройством программы.
В main владелец отвечает за delete dynamic; alias только обращается к той же точке.
В CirclePtr владелец — сам CirclePtr, он удаляет center_ в своём деструкторе.

Деструктор и освобождение памяти — связанные, но не тождественные действия:
например, деструктор локального Point вызывается без delete.
В реальных проектах владение часто выражают умными указателями,
но их изучение в этой методичке относится к ЛР5.

## 8. Наследование

`class ColoredPoint : public Point` означает: цветная точка является разновидностью точки.
Она содержит базовую часть Point и дополнительное поле color_.
Открытые методы Point доступны у ColoredPoint, например Move.
При public-наследовании public остаётся public, protected остаётся protected;
private-поля предка напрямую недоступны.

Сначала создаётся базовая часть Point, затем поля ColoredPoint, затем выполняется
тело конструктора ColoredPoint. Уничтожение идёт наоборот:
тело ~ColoredPoint, его поля, затем базовая часть Point.

```text
Point(x, y)
ColoredPoint(x, y, color)
...
~ColoredPoint
~Point (9, 10)
```

В PlainPoint мы не пишем собственные конструктор и деструктор.
Компилятор неявно создаёт нужные методы: при создании PlainPoint вызывается Point(),
при уничтожении — ~Point(). Отсутствие написанного метода не означает отсутствие создания/уничтожения.
При `PlainPoint copy(plain)` неявный конструктор копирования потомка вызывает
`Point(const Point&)` для базовой части. Изменение copy не меняет plain.
Если у предка нет доступного конструктора без параметров, пустой наследник
так автоматически создаваться не сможет.

## 9. Указатель на предка и методы без virtual

```cpp
ColoredPoint colored(5, 6, 1);
Point* base = &colored;
colored.Print(); // ColoredPoint::Print
base->Print();   // Point::Print
```

Объект один, он остаётся ColoredPoint. Статический тип base — Point*.
Без virtual реализация Print выбирается по типу выражения, через которое вызван метод.
Наличие Print в ColoredPoint не делает метод виртуальным автоматически.
Строго в C++ это сокрытие невиртуального метода; методичка использует слово «переопределение».
Настоящее виртуальное переопределение и динамический полиморфизм изучаются подробнее в ЛР5.
Слово override здесь писать нельзя: метод предка не virtual.

`base->SetColor(3)` не компилируется: в интерфейсе Point нет SetColor.
Внутри ColoredPoint::Print явный вызов `Point::Print()` показывает обращение к методу предка.
Именно поэтому при colored.Print() выводятся и строка ColoredPoint, и строка Point.

```cpp
Point* p = new Point(7, 8);       // Создан именно Point.
ColoredPoint* d = new ColoredPoint(9, 10, 3);
Point* view = d;                 // Создан ColoredPoint, view видит интерфейс Point.
delete d;                       // Корректно: удаление через тип ColoredPoint*.
delete p;                       // Корректно: объект Point, указатель Point*.
```

У Point деструктор невиртуальный. `delete view` для указанного ColoredPoint
было бы неопределённым поведением; неверно говорить, что «просто вызовется только ~Point».
Чтобы безопасно удалять потомков через Point*, потребовался бы виртуальный деструктор.
В нашей программе такой способ удаления не используется.
После delete d указатель view тоже становится висячим, хотя сам отдельно не удалялся.

## 10. Срезка объекта

```cpp
Point sliced = colored;
```

Создаётся новый объект Point; его конструктор копирования копирует базовую часть colored.
У sliced есть только координаты, отдельного поля color_ у него нет.
Это срезка (object slicing). Исходный colored не превращается в Point и не теряет свой цвет.
При работе через Point* копии и срезки нет: указатель ссылается на исходный объект-потомок.

## 11. Композиция и агрегация

Наследование отвечает «является разновидностью»: ColoredPoint является Point.
Композиция отвечает «владеет частью»: Circle владеет своим центром Point.

| Вариант | Создание центра | Уничтожение центра | Ответственность |
| --- | --- | --- | --- |
| `Point center_` в Circle | Автоматически до тела конструктора Circle, через список инициализации | Автоматически после тела деструктора Circle | Язык управляет полем-объектом |
| `Point* center_` в CirclePtr | Явное new в списке инициализации конструктора | Явное delete в теле деструктора CirclePtr | Код CirclePtr |
| Агрегация, пример в теории | Готовый Point создаёт внешний код | Тоже внешний код | Объект ссылается на чужую точку, не владеет ею |

В CirclePtr также композиция, хотя используется указатель: CirclePtr создаёт часть,
единолично владеет ею и уничтожает. Само наличие указателя НЕ определяет вид отношения.

Пример агрегации только для объяснения, не отдельное задание программы:

```cpp
class PointView {
    Point* point_; // Не владеет. В деструкторе delete не нужен.
public:
    explicit PointView(Point& point) : point_(&point) {}
};
```

Точка существует независимо от PointView и должна жить дольше обращений PointView к ней.
Удаление PointView не должно уничтожать внешнюю точку.
Агрегация не отменяет риска висячего указателя: если внешняя точка уже уничтожена,
обращаться к ней через сохранённый адрес нельзя.
Термин «агрегат» в правилах инициализации C++ — другая тема, не определение агрегации ООП.

## 12. Копирование и владение

Копия Point содержит собственные числа. Копия Circle содержит отдельный Point-поле.
Если же скопировать только адрес center_ у CirclePtr, два круга начнут считать
своей одну точку. Изменения станут общими, а два деструктора попытаются удалить её дважды.

Поэтому конструктор копирования CirclePtr выполняет:

```cpp
center_(new Point(*other.center_))
```

`other.center_` — адрес центра оригинала; `*other.center_` — сама точка;
`new Point(...)` создаёт её отдельную копию. Это глубокое копирование.
В демонстрации у оригинала центр (1, 22), у копии (11, 2): их изменения независимы.

Похожая запись `a = b` для УЖЕ существующих CirclePtr — другой механизм,
оператор присваивания. Его неявное поведение скопировало бы только адрес, что опасно.
Поэтому присваивание CirclePtr явно запрещено строкой `operator=(...) = delete`.
`= delete` в объявлении метода означает запрет вызова; это не инструкция освобождения памяти.
`CirclePtr b(a)` и `CirclePtr b = a` разрешены: здесь создаётся новый объект конструктором копирования.

Для Point строка `operator=(...) = default` просит компилятор выполнить обычное
присваивание полей: два целых числа безопасно копируются.
Это не новая сложная функция с пользовательским алгоритмом.
Общий принцип, известный как правило трёх: если класс управляет ресурсом и ему
нужны собственные деструктор/копирование, нужно также продумать присваивание.
Его можно корректно реализовать или запретить; в нашей работе выбран запрет для CirclePtr.

## 13. Вопросы для самопроверки

1. Сколько объектов создаёт `Point* a = new Point; Point* b = a;`?
   Один Point и две переменные-указателя. Второе присваивание не создаёт точку.
2. Нужно ли делать delete для обычного локального Point?
   Нет, его время жизни заканчивается автоматически при выходе из блока.
3. Вызовется ли деструктор при `p = nullptr`?
   Нет. Динамический объект при этом остаётся; можно потерять его адрес и получить утечку.
4. Можно ли читать private-поле предка в потомке?
   Напрямую нельзя; используют доступные методы предка.
5. Всегда ли наследование даёт вызов метода потомка через указатель предка?
   Нет. Для такого выбора реализации нужен виртуальный метод; у нас методы невиртуальные.
6. Можно ли сделать конструктор virtual?
   Нет. Виртуальных конструкторов в C++ нет.
7. Почему у обычной композиции вывод ~Circle идёт перед ~Point?
   Сначала выполняется тело деструктора Circle, затем автоматически уничтожаются его поля.
8. Почему CirclePtr не является агрегацией?
   Он владеет своим центром и отвечает за его уничтожение.
9. Что означает const Point& в конструкторе копирования?
   Существующий объект передаётся по ссылке без дополнительной копии и без изменения через ссылку.
10. Почему конструктор копирования не принимает Point по значению?
    Для передачи по значению пришлось бы создать копию ещё до входа в него;
    такой конструктор копирования по значению недопустим.
11. Может ли два указателя быть владельцами одной точки?
    В этой программе владелец один. Если оба самостоятельно сделают delete, будет двойное удаление.
12. Зачем в коде PlainPoint?
    Чтобы показать отдельный обязательный случай: наследник без написанных им конструктора и деструктора.

### Задание 1: точка по умолчанию должна иметь координаты (10, 20)

В objects.cpp меняется только список инициализации Point():

```cpp
Point::Point() : x_(10), y_(20) {
    std::cout << "Point()\n";
}
```

Изменятся также центры Circle и CirclePtr, созданных без параметров, и базовая часть

### Задание 2: добавить метод SetXY

В public-раздел Point в objects.h:

```cpp
void SetXY(int x, int y);
```

В objects.cpp:

```cpp
void Point::SetXY(int x, int y) {
    std::cout << "Point::SetXY\n";
```

В main можно вызвать `original.SetXY(7, 8);`. Метод будет доступен и ColoredPoint
