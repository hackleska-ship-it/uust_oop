## Запуск в Windows

При первом запуске выполни `setup.bat` в папке `lab_3`.
Он создаёт локальное окружение `.venv` и устанавливает зависимости.
На компьютере должен быть установлен Python 3.10 или новее.

После настройки достаточно открыть один из файлов:

- `run_circles.bat` — первая часть;
- `run_mvc.bat` — вторая часть.

Те же действия из терминала в папке `lab_3`:

```bat
setup.bat
run.bat circles
run.bat mvc
```

Если Python находится вне PATH, перед настройкой можно задать `PYTHON_EXE`
с полным путём к его исполняемому файлу. Готовое окружение `.venv`
на другой компьютер не копируется: там нужно повторить настройку.

## Запуск в macOS и Linux

В терминале из папки `lab_3`:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py circles
python run.py mvc
```

Части также запускаются отдельно: `python part_1/main.py` и
`python part_2/main.py` в активированном окружении.

## Часть 1 — Круги на форме

`CCircle` хранит закрытые координаты, признак выделения и постоянный радиус 30.
Объект сам проверяет попадание мыши и рисует себя. Форма не читает его координаты.
`CircleStorage` содержит закрытый список кругов; снаружи доступны добавление,
перебор, поиск попаданий и удаление выделенных объектов.

Управление:

- ЛКМ по пустому месту создаёт и выделяет новый круг.
- ЛКМ по кругу выделяет его, снимая остальное выделение.
- Ctrl + ЛКМ добавляет круг к выделению или снимает выделение с него.
- Delete удаляет все выделенные круги.
- Изменение размера окна сохраняет круги и вызывает их перерисовку.

В пересечении по умолчанию выбирается верхний круг — последний нарисованный.
Чтобы выбирать сразу все круги под указателем, в `PaintArea` достаточно
изменить `SELECT_ALL_ON_HIT` на `True`.

## Часть 2 — MVC

Отдельная модель `NumberModel` хранит целые числа и обеспечивает
`0 <= A <= B <= C <= 100`.

- При увеличении A модель при необходимости повышает B и C, сохраняя новое A.
- При уменьшении C модель при необходимости понижает B и A, сохраняя новое C.
- B ограничивается ближайшим допустимым значением между A и C.
- Ограничение диапазона 0–100 задаётся в модели. Форма получает его через свойства.
- Сначала устанавливается весь согласованный набор, затем испускается один сигнал.
- Неизменившиеся значения не вызывают уведомлений. При запуске форма обновляется один раз.

Каждое число редактируется через текстовое поле, счётчик и ползунок.
Текстовое поле подтверждается Enter или потерей фокуса. Пустой и нечисловой ввод
при завершении редактирования заменяется текущим значением модели.
Обновление виджетов блокирует их обратные сигналы, поэтому не возникает циклов обновления.
Количество обновлений видно внизу окна и в консоли.

Модель сама сохраняет изменившиеся значения через `QSettings` и восстанавливает
их при следующем запуске. Хранилище приложения — `UUST / BashirovLab3MVC`:
системный реестр в Windows, настройки пользователя Qt на других платформах.
Форма не читает и не записывает настройки.
В тестах используется отдельный временный INI-файл; личные сохранённые значения не затрагиваются.

Отдельный класс-контроллер не нужен: обработчики представления передают числа
методам модели, а представление подписывается на её сигнал `changed`.
С моделью можно работать без создания формы, используя `QCoreApplication`.

## Проверки

В Windows из папки `lab_3`:

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В macOS/Linux в активированном окружении:

```sh
python -m unittest discover -s tests -v
```

Тесты используют настоящие Qt-виджеты с платформой `offscreen` и не открывают
окна поверх рабочего стола. Проверяются оба правила выделения, Ctrl, Delete,
попадание на границе, отрисовка после изменения размера, все девять элементов
MVC, исправление некорректного ввода, сохранение и работа модели без формы.
Для 300 последовательных изменений проверяются ограничения, атомарность и число сигналов.
