# Вопросы к защите ЛР № 3

## Круги на форме

**Почему нельзя рисовать только в обработчике щелчка?**
Окно может перекрыться другим окном или изменить размер. Qt тогда повторно
вызывает `paintEvent`, который должен восстановить изображение по данным контейнера.
Обработчик мыши меняет данные и вызывает `update`, а рисование выполняется в Paint.

**Что делает круг, а что делает форма?**
Круг знает свой центр, радиус и выделение, умеет рисоваться и проверять попадание.
Форма получает событие мыши, просит контейнер найти объекты, меняет выделение
и запрашивает перерисовку. Форма не читает координаты кругов.

**Зачем свой контейнер, если уже есть list?**
`CircleStorage` скрывает внутренний список и предоставляет операции коллекции.
Внутреннее хранение можно изменить, сохранив внешний интерфейс.
`for circle in storage` использует `__iter__`, а `len(storage)` — `__len__`.

**Почему в пересечении выбирается последний круг?**
Объекты рисуются в порядке добавления. Последний виден поверх предыдущих,
поэтому поиск выполняется в обратном порядке. Для выбора всех достаточно
переключить `PaintArea.SELECT_ALL_ON_HIT` на `True`.

**Что происходит при Delete?**
Контейнер исключает выделенные круги из своего списка. Когда ссылок на объект
больше нет, его память освобождается средствами Python. Рисование при следующем
Paint видит уже сокращённую коллекцию. Удалять элементы из перебираемого списка
по одному не требуется: строится новый список оставшихся объектов.

## MVC

**Где модель, представление и контроллер?**
`NumberModel` — модель, окно и строки `NumberRow` — представление с обработчиками
ввода. Отдельного контроллера нет: дополнительный класс здесь не нужен.
Обработчик преобразует текст в число и вызывает метод модели. Все правила — в модели.

**Чем отличаются правила A, B и C?**
При изменении A или C пользовательская граница сохраняется, а соседние числа
при необходимости перестраиваются. Для B модель выбирает ближайшую допустимую
точку интервала от A до C. Сам диапазон 0–100 применяется в модели ко всем числам.

**Что такое атомарное изменение?**
Подписчик получает только полностью согласованный набор. Даже если изменились
все три числа, сначала устанавливаются три поля, а затем испускается один сигнал.
Подписчик может вызвать `values` и получить тот же набор, который пришёл в сигнале.

**Почему сигналы виджетов надо блокировать при обновлении?**
`setValue` может испустить `valueChanged`. Если обработчик снова вызовет модель,
образуется лишняя цепочка вызовов. `QSignalBlocker` временно блокирует сигнал,
а при выходе из блока восстанавливает предыдущее состояние даже при исключении.

**Как происходит запуск и сохранение?**
Создаётся модель, затем окно подключается к `changed`. Модель самостоятельно
загружает и нормализует значения в `initialize` и сообщает итог одним сигналом.
Каждое последующее изменение сохраняется моделью через `QSettings`.
Повторный `initialize` не вызывает второй стартовый сигнал.

**Почему пустое поле не ломает модель?**
Пока пользователь печатает, текст может быть промежуточным. При Enter или
потере фокуса обработчик передаёт целое число модели либо восстанавливает
текущее значение. Сама модель не принимает строки, `None`, дробные числа и bool.

**Как показать самодостаточность модели?**
Создать `QCoreApplication`, модель и отдельное временное `QSettings`, подписаться
на сигнал, вызвать `initialize` и сеттеры. Ни окно, ни виджеты для этого не нужны.
Такой сценарий выполняется автоматическим тестом в отдельном процессе.
